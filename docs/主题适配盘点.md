# 主题适配盘点（Arknights 皮肤 · 浅色 / 暗色 / 自动偏好）

状态：**已上线**（2026-09-29 21:27–21:36，99 页；之后补 `模块:EventShopList`、编辑页提示框、行内图片对齐，BotCathPalug）。沙箱先落地复测，线上抽测 12 页结果一致。落地记录见 §13，拍板见 §12。

## 1. 背景

新皮肤有三种外观，由 `<html>` 上的类决定：

| 用户选择 | html 类 | 什么时候是暗色 |
| --- | --- | --- |
| 浅色 | `skin-theme-clientpref-day` | 从不 |
| 暗色 | `skin-theme-clientpref-night` | 始终 |
| 自动（默认） | `skin-theme-clientpref-os` | 系统 `prefers-color-scheme: dark` 时 |

站内模板的暗色适配是在 Vector 时期做的，换皮肤后暴露出四类问题：

| 类 | 现象 | 根因 |
| --- | --- | --- |
| A | 自动偏好 + 系统暗色下，模板仍是浅色底，文字看不清 | 样式只写了 `night` 选择器，没有 `os` 分支 |
| B | 暗色规则在新皮肤下三种外观都不生效 | 选择器限定了 `body.skin-vector-2022` |
| C | **浅色**下深底深字 | 行内写 `--color-base:#fff` 指望文字变白；新皮肤不吃这个变量 |
| D | 暗色下浅底浅字 | 行内写死浅色底，从来没有暗色适配（以前靠 darkModeFix 兜底或干脆没管） |

最初的报告：干员一览的 Cbox2、干员页的 Pathnav2 和模组表格（A 类），干员页获得方式表格（C 类）。

## 2. 盘点方法

两种手段互补，缺一不可：

**静态扫描**：拉现网 `MediaWiki` / `模板` / `微件` 三个名字空间共 1861 页，比对每个样式表里
`night` 与 `os` 选择器（去重后逐个对应），并检查是否带皮肤作用域。能查全 A、B 两类，查不到行内写死的颜色。

**渲染审计**（`scripts/theme_audit.py`）：

1. 从沙箱库 `templatelinks` 做贪心集合覆盖，选出 158 个页面，覆盖主名字空间引用到的全部 586 个模板 / 微件 / 模块
2. 无头浏览器逐页渲染，每页切三种外观，量正文每段文字与**实际背景**的对比度，低于 3:1 记为问题
3. 滤掉「设计如此」：浅色以 Vector 浅色渲染为参照，暗色以本皮肤浅色为参照，参照里原样存在的低对比度（彩色徽章等）不算。共滤掉 377 条
4. 按问题元素的类名（或行内底色）在页面所用模板的源码里匹配，归因到模板

结果：158 页全部渲染成功，**51 个模板 / 模块有问题**，另有 269 条归不到模板。明细见 `reports/theme-audit.md`。

### 局限

- **归因是近似的**。类名被多个模板共用时会各记一次。已知两处偏差：记在 `模板:Purge` 名下的实为 `模板:Shortcut` 的快捷方式框；记在 `模板:参阅` 名下的是 Cbox2 里正文写的灰色文字。动手前要看明细核对
- 折叠、标签页里未展开的内容量不到
- 沙箱库比线上旧，2026 年 9 月之后新增的模板和页面不在渲染审计范围内（静态扫描用的是现网数据，不受影响）
- 背景是渐变或图片的元素算不准，一律跳过

### 3.4 修法

`wikibot/theme_os.py` 把每条 night 规则机械复制一份：选择器换成 `-os`，外面包
`@media (prefers-color-scheme: dark)`，集中追加到样式表末尾的标记区块里。

```css
/* theme-os:begin 自动偏好（跟随系统暗色）。由上方 night 规则机械生成，勿手改 */
@media (prefers-color-scheme: dark) {
  html.skin-theme-clientpref-os body .pathnav2-right {
    background: #2f3136 !important;
    …
  }
}
/* theme-os:end */
```

- **幂等**：重跑只重新生成这个区块。以后改了 night 规则，重跑一次即可同步
- 已手写过等价 os 规则的选择器不重复生成
- 原来套在 `@media screen` 里的规则，生成为 `@media screen and (prefers-color-scheme: dark)`
- 重复书写的选择器（Pathnav2 每个都写了两遍）自动合并

```bash
uv run python scripts/theme_os_apply.py --dry-run --show-diff 模板:Cbox2/styles.css
uv run python scripts/theme_os_apply.py -c config.sandbox.toml --from-live 模板:Cbox2/styles.css
```

`--from-live` 先取线上当前正文再生成，用于沙箱库比线上旧的情况；对线上站点使用会直接报错退出。

微件的样式嵌在 `<style>` 标签里，脚本目前只处理独立样式表，5 个微件需要手工处理或扩展脚本。

## 5. C 类：浅色下深底深字

Vector 的正文颜色走 `var(--color-base)`，所以在容器上覆盖这个变量能把里面的文字整体变白。
新皮肤的 `tables.css` 直接写 `color: var(--ak-fg)`，覆盖 `--color-base` 无效。

| 位置 | 引用量 | 渲染审计结果 |
| --- | ---: | --- |
| `.mw-collapsible-dark`（`MediaWiki:Common.css`） | 样本中 14+ 页 | 表头 `#343434` 配 `#1d1f20`，1.33 |
| `.prts-table-ra-token`（`MediaWiki:Common.css`） | — | 同样写法，未在样本中触发 |
| `模板:敌方情报/标题行`、`模板:敌方情报` | 3332 | 表头 `#575757` 上的链接，1.37 |
| `模板:干员获得方式` | 456 | `#404040` 底，1.6 |
| `模块:IngameStory` | 236 | 同上 |
| `模板:剿灭关卡信息` | 36 | 同上 |
| `模板:剿灭作战进度奖励` | 35 | 同上 |
| `模板:收藏品`、`模板:收藏品/pro` | 15 | 同上 |
| `模板:集成战略道具` | 3 | 同上 |
| `模板:生息演算道具`、`/资源`、`/信物` | 4 | 同上 |
| `模板:测试指标/全息/style` | 8 | 同上 |
| `模板:制作组通讯往期阅读` | — | 静态扫描命中，未在样本中触发 |

**修法**：在写 `--color-base` 的同一处补显式 `color`。保留原变量，Vector 下行为不变：

```diff
- style="--color-base:#FFFFFF; background-color:#404040;"
+ style="--color-base:#FFFFFF; color:#FFFFFF; background-color:#404040;"
```

> **落地时修正**：只在表格上补 `color` 管不到表头。皮肤 `tables.css` 的
> `.wikitable > * > tr > th { color: var(--ak-fg) }`（0,1,3）直接给 th 上色，压过继承来的颜色；
> Vector 下 th 能变白是因为 Vector.css 写的是 `color: var(--color-base, unset)`。实际做法：
>
> - 整张表都是深色底的（收藏品、集成战略道具、生息演算道具、干员获得方式）：表格挂
>   `prts-table-dark`，Common.css 里让它的表头跟随表格的白字
> - 单个深色表头（敌方情报/标题行、剿灭作战进度奖励）：挂 `prts-cell-dark`，文字白色，
>   里面的链接和折叠按钮跟随文字色
> - 其余在表头的行内样式里直接补 `color`（剿灭关卡信息）
>
> 折叠按钮是 `<button>`，皮肤给按钮、核心给按钮文字（`.mw-collapsible-toggle-default .mw-collapsible-text
> { color: var(--color-progressive) }`）各上了一次链接色，要两层一起改。
> `.mw-collapsible-dark` 的按钮不用动：上方变量块把 `--color-progressive` 设成了橙色。

深色表头里的链接还要单独处理（皮肤的链接色 `#0072a8` 在深底上只有 1.37–1.9），
建议在对应的 styles.css 里给深底容器内的 `a` 指定浅色。

`.mw-collapsible-dark` 改 Common.css 一处就能修掉一大片，**建议最先做**。

### 7.2 要做的事

**第一步：把 Vector 的配色搬进 `模板:Navbox/styles.css`**（基础态，三种外观、所有皮肤生效）

```css
/* 配色（自 MediaWiki:Vector.css 分流；2026-09-29 拍板保留 Vector 三级蓝） */
.navbox {
  border: 1px solid #a2a9b1;
  font-size: 88%;
}
.navbox,
.navbox-subgroup {
  background: #fdfdfd;
}
.navbox-list {
  border-color: #fdfdfd;
}
.navbox th,
.navbox-title {
  background: #4487df;
}
.navbox-title a,
.navbox-title div {
  color: #fff;
}
.navbox-abovebelow,
th.navbox-group,
.navbox-subgroup .navbox-title {
  background: #85c1f7;
}
.navbox-subgroup .navbox-group,
.navbox-subgroup .navbox-abovebelow {
  background: #ebf7fe;
}
.navbox-even {
  background: #f7f7f7;
}
.navbox-odd {
  background: transparent;
}
```

注意三点：

- 现有的 `.navbox-list { border-color: transparent }` 要换回 `#fdfdfd`（或保持透明，效果相同，二选一即可）
- 皮肤 `catlinks.css:60-64` 的选择器是 `.mw-parser-output .navbox …`，优先级高于上面的裸类选择器。
  要么 TemplateStyles 里同样带 `.mw-parser-output` 前缀并靠加载顺序取胜，要么从皮肤里删掉那五行。
  **拍板：用 TemplateStyles 覆盖，皮肤不改。** TemplateStyles 本来就会给每个选择器加 `.mw-parser-output`
  前缀，与皮肤同特指度，且 `<style>` 在正文里、晚于皮肤样式加载，所以直接胜出。除颜色外还覆盖了标题左侧的
  强调条（`border-left: 0`，蓝底上再压一条青色竖条不成样子）；字号、内边距不在「配色」范围内，没有搬 `font-size: 88%`
- 浅色下白字配 `#4487DF` 的对比度是 3.6，配 `#85C1F7` 只有 1.9。分组标题现在是黑字所以没问题，但
  Pathnav2 中段白字配 `#85c1f7` 在审计里被记为「设计如此」滤掉了——保留配色就意味着保留这一点

**第二步：暗色规则去掉 Vector 作用域，补全缺的部分**
