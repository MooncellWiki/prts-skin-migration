# 表格定宽迁移（`table-fixed-width`）

2026-10-01 · 机器人账号 BotCathPalug · 规则 `wikibot/rules/skin.py` 的 `TableFixedWidthRule`

## 问题

内容里大量表格写死像素宽度（`{| style="width:800px; display:table"`）。WebKit（iOS 上所有浏览器，
包括 Chrome）的自动表格布局把定长 `width` 当成表格的最小宽度，新皮肤在 <640 时给 `.wikitable` 的
`max-width:100%` 压不住，手机上整页被撑宽、能左右拖。Blink 能压住，所以只有 iOS 上出事。

旧移动站（m.prts.wiki）没出过事，是因为 Minerva 在 <640 时给 `.content table` 写了
`width:100% !important`，把内联宽度整个盖掉了；模板里成片的 `display:table` 则是为了顶掉同一条规则里的
`display:block`。内容本身从来不是响应式的。

## 改法

只改表格开头（wikitext `{|` 行 / HTML `<table>`）里宽于 300px 的定长 `width`，原地替换：

```
width:800px            →  width:min(800px, 100%)
width="800"（属性）     →  去掉属性，style 里加 width:min(800px, 100%)
```

（最早 7 个页面先按「保留旧值、后面追加一条」的写法提交过，随后统一收成上面这一条。
旧值只是给不认 `min()` 的浏览器——2020 年前的 Chrome 79 / Safari 11.1 / Firefox 75 之前——留的回落，
现代浏览器里后一条总会覆盖前一条，去掉它不改变渲染。）

为什么是这个写法而不是 `width:100%; max-width:800px`：要求**现有渲染不变**。

- 桌面：容器不窄于 800px 时 `min(800px, 100%)` 就是 800px，与原来相同；
- Minerva（<640）：`width:100% !important` 把两条声明一起盖掉，与原来相同；
  而 `max-width` 会把本该拉满的窄表封顶，手机端会变；
- 新皮肤 / WebKit：`min()` 不是定长，不触发上面的怪癖，表格不再撑破页面。

## 验证：按布局环境归类，而不是逐页

`min(800px, 100%)` 与 `800px` 只在一种情况下不等价：表格的父容器宽度本身由表格撑出来
（单元格里、浮动 / inline-block / flex 容器里、绝对定位里）。这时百分比让容器改按内容收缩，表格跟着变窄。

1. **抓渲染 HTML**：直接改动的 1641 个页面全量；被改的 72 个模板共 13713 个引用页里，
   每模板随机抽 25 个，另外对全部引用页做调用位置的静态分析（是否顶层调用），
   1066 个非顶层调用的页面全部补抓。共 3391 个页面、15815 张要改的表格。
2. **归类**：每张表按「正文根 → 表格」的祖先链（标签、class、影响布局的内联样式）分组，共 61 组。
   单元格内 / inline-block·flex·grid 内 / 绝对定位内 / 浮动容器内（含 `thumb tright` 等）18 组共 104 张表
   列入跳过名单（`skip.json`，按「页面或模板 → 表格 style 原文」记录），其余 43 组照改。
3. **浏览器验证**：每组挑若干代表页（贪心覆盖组内不同的表格样式），在 7 种环境下渲染，
   量一遍 → 页内套用与规则相同的改写（跳过名单同样生效）→ 再量一遍，比对每张表的位置尺寸与整页宽高：
   Vector 1920 / 1280、Vector 2022 1920、桌面 Safari 1440、Minerva 390、Minerva 768、新皮肤 WebKit 440。
   隐藏的 tabber 面板、折叠块、自制标签页强制显示后再量。
