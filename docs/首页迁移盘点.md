## 1. 首页现状

`首页`（ns 0）不是一个页面，是**两个页面**：

```
首页
├── {{#Widget:mpstyle}}                    ← 13.9 KB 原始 <style>，整张首页的 CSS 都在这
├── <div class="nomobile"> 桌面版           ← 无 i18n，h2 用裸 HTML 标签
│   ├── <center>{{首页轮播}}</center>       ← SMW #ask → {{首页轮播/div}} → {{#Widget:Mp-carousel-div}}
│   ├── {{Ads/normal}}                     ← 空页面
│   ├── #mpbutton-container > #mpbutton-scaler > 12×{{mpbutton}} + {{#widget:mpbutton}}
│   ├── 今日信息  {{行动日历}} + {{当前信息}}
│   ├── 亮点干员  {{:首页/亮点干员}}（生日 / 近期新增 / 凭证兑换 / 新增皮肤 / 新增模组 / 寻访提升）
│   ├── 近期新增  {{:首页/新增关卡}} {{:首页/新增主题}} {{:首页/新增单件}}
│   └── 网站信息  {{mdi|…}} {{fa|…}} 图标字体
└── <div class="nodesktop">{{:首页/mobile}} ← 移动版：有 {{#tsl:}} 中/日/英三语，h3，无行动日历、无 Ads/normal
```

数据来源：SMW（轮播的活动 / 寻访）、`PRTS:Gameinfo/国服/*`（维护时间、赛季、机制开关，用 `#lst` 分段引用）、
`{{#Widget:Time}}` / `{{#Widget:倒计时/js}}`（时钟与倒计时）、`Special:Gadgets` 的 `Carousel` + `slick`（轮播行为）。

## 3. 已定的两件事

### G6 · MobileFrontend / Minerva 下线，全站统一 Arknights

这条决定了整个迁移的规模。连带要清的：

| 对象 | 量 | 处理 |
| --- | --- | --- |
| `.nomobile` / `.nodesktop` 双份渲染 | 88 个页面 / 226 处（模板 70 · 微件 6 · 模块 3 · MediaWiki 9） | 合并成一份响应式；机器人能定位，合并要人工 |
| `首页/mobile` | 1 个页面 | 并入 `首页` 后退役 |
| `MediaWiki:Mobile.css` `Minerva.css` | 22.4 KB + 10.9 KB | 随皮肤退役 |
| `skins=minerva` 的小工具 | 3 个（`Summer2022_m` `fourthStyle_m` `Summer2023_m`） | 退役 |

顺带作废的还有 `MediaWiki:Vector.css`（46.3 KB）、`Vector-2022.css`（12.2 KB）、`Vector.js` ——
四个皮肤的站点 CSS 加起来约 **92 KB 直接退役**。留下的只有 `Common.css`（7.8 KB）与 `Common.js`（2.6 KB），
它们在任何皮肤下都加载，需要单独审（`Common.css` 里有 6 处旧皮肤选择器，另外 `--additon-title` 也定义在这里）。

### G1 · TemplateStyles 放行 Mooncell 自家域名（已落地）

按域名通配 `(?:[a-z0-9-]+\.)*(?:prts|fgo|mooncell)\.wiki`，一次覆盖 prts / fgo 两站及以后新增的图床子域。
沙箱 19 个用例全过：协议相对写法与大写主机名放行，`prts.wiki.evil.com` / `evilprts.wiki` 等绕过被挡，
`data:` 与 `@font-face` 有意仍拒绝。它只放宽保存校验、不改渲染（现网 73 个 TemplateStyles 页面 `url()` 出现 0 次），
所以不必等切换窗口。详见 [migration/patches/README.md](../migration/patches/README.md) 的 0001。

## 5. `微件:Mpstyle` —— 全删，不迁移

13.9 KB / 71 条规则、150 个选择器。原先打算把其中「页面自己的样式」那 41 个选择器迁进
`模板:首页/styles.css`，**结论是不迁，全删**，新样式按设计稿重写。三条理由：

**一、按桶算，109 / 150（73%）本来就是直接删**

| 桶 | 选择器数 | 为什么删 |
| --- | ---: | --- |
| 旧皮肤补丁 / 手写暗色（`skin-vector` `skin-minerva` `page-首页` `clientpref-night` …） | 80 | 随皮肤作废 |
| 移动版专用（`.mp-mobile-*` `.mp-m-*`） | 25 | 随 G6 作废 |
| slick 轮播（`.slick-*` `.carousel-*` `.weekly-indicator`） | 4 | 随 Swiper 作废 |
| 页面自己的样式（`.mp-today` `.mp-extranav` `.mp-siteinfo` `.mp-operators` …） | 41 | 见下 |

**二、剩下的 41 个，设计稿全都覆盖了，而且更准**

逐条对过，没有一条带着「删掉就丢」的信息：

| 现网 | 设计稿对应 | 备注 |
| --- | --- | --- |
| `.mp-bili-charge-btn` `#f25d8e` | `.mp-brand--bilibili` `#FB7299` | 设计稿用的是官方现行品牌色，现网是老的近似值 |
| `.mp-double-donate-btn` 微信 `#44b549` / 支付宝 `#00aaee` | `.mp-brand--wechat` `#07C160` / `.mp-brand--alipay` `#1677FF` | 同上 |
| `.mp-status-light` + `@keyframes status-light` | `ak-blink` | 皮肤组件层已有 |
| `.mp-operators-title` 下划线 | `.ak-heading` | 同上 |
| `.mp-container-left 58%` / `-right 41%` + `@media (max-width:1500px)` | 设计稿自己的栅格与断点 | 布局整体重排，比例无意义 |

## 7. 数据接线（G8 / G9 / 网页活动）

### G8 · 行动日历的「特别开放周」——不需要新数据源

**更正上一版的判断**：我先前写「现网行动日历是纯算的、零维护，设计稿新增了人工维护」，这不对。
`模板:行动日历` 第一行就在读全开周配置：

```wikitext
{{#vardefine:weekday|{{#ifexpr:{{#iferror:
  {{#time:U|+8 hours}} >  {{#time:U|{{#lst:PRTS:Gameinfo/国服/基础|cndlystart}}}} and
  {{#time:U|+8 hours}} <= {{#time:U|{{#lst:PRTS:Gameinfo/国服/基础|cndlyend}}}}
}}|8|{{#time:N|+4 hours}}}}}}
```

`weekday = 8` 就是「全天开放」那一档。也就是说**配置早就存在，也早就在人工维护，而且就在
`PRTS:Gameinfo` 里**——正是要暴露的位置：

```wikitext
*资源关卡全开-起始：<section class="lst" begin=cndlystart />2026-06-26 16:00<section class="lst" end=cndlystart />
*资源关卡全开-结束：<section class="lst" begin=cndlyend  />2026-07-10 03:59<section class="lst" end=cndlyend  />
```

新首页要做的只是把它换个出口——设计稿要的是容器上的 `data-force-open="起/止"`（ISO，+08:00）：

```wikitext
<div class="mp-today__res" id="mp-res" data-force-open="{{#time:Y-m-d\TH:i:s|{{#lst:PRTS:Gameinfo/国服/基础|cndlystart}}}}+08:00/{{#time:Y-m-d\TH:i:s|{{#lst:PRTS:Gameinfo/国服/基础|cndlyend}}}}+08:00">
```

- 存的是北京时间墙钟值，`#time` 不带时区参数时按 UTC 解析再原样输出，等价于纯格式转换，末尾补 `+08:00` 即可——
  和 `行动日历` 现有的 `{{#time:U|+8 hours}}` 是同一套假设。

## 8. 设计稿 → wikitext 的实测限制（还原验证得出）

在现网 `首页/sandbox` 把设计稿整页搬进去跑通之后，暴露出一批**设计稿与 wikitext 之间的硬限制**。
这些不是首页独有的，凡是「设计稿画好、要落成 wiki 页面」的都会撞上。

| 限制 | 现象 | 处理 |
| --- | --- | --- |
| **CSS 不能走 TemplateStyles** | css-sanitizer v5.5.0 不认自定义属性定义（`--x: red`），`var()` 嵌在 `calc()`/简写/`gap` 里也不认；`aspect-ratio` `mask-image` `clamp()` `:focus-visible` `:is()` `:has()` 全部丢弃。设计稿 38.7 KB 灌进去只剩 22 KB | 走微件（原始 `<style>`，无净化器）。**生产环境应当归皮肤**——`.mp-hero` 那套局部重映射令牌是设计的核心手法，TemplateStyles 永远支持不了 |
| **`<a>` 不在白名单** | 设计稿把 `<a>` 当块级容器用（hero 图、候选项、12 宫格、干员卡…），wikitext 里 118 处全被转义成可见文本 | 转 `<span>/<div> + data-href` + 点击代理。**生产环境应当用现网 Mpbutton 那种「容器 + 透明覆盖链接」**（`[[文件:mask.png\|link=目标]]`），无 JS 也能点 |
| **`<button>` `<nav>` `<input>` `<svg>` 也不在白名单** | 同样被转义（`<section>` 倒是允许） | `<button>`→`<span role=button>`、`<nav>`→`<div>`、`<svg><use>`→CSS `mask-image` 类、`<input>` 直接去掉 |
| **行首空格 = 预格式化块** | 设计稿的 HTML 是带缩进的漂亮排版，整段被包进 `<pre>`，hero 工具栏因此错位 | 逐行去掉行首缩进 |
| **连续行内元素会被套 `<p>`** | `<a>` 统一转 `<span>` 后，12 宫格的每个格子各自被包进一个 `<p>`，网格塌成一列 | 按设计稿自己声明的 `display` 判断转 `<div>` 还是 `<span>` |
| **空行 = 空 `<p>`** | 整页 HTML 之间的空行生成 20 个空段落 | 去掉空行 |
| **`首页/sandbox` 拿不到首页版式** | 皮肤的 `is-mainpage-view` 只认 `Title::isMainPage()`，sandbox 页没有 `.ak-layout--mainpage`，按普通阅读列渲染 | 不补——sandbox 页按普通页面的版式显示（白纸卡片 + 阅读列宽），首页版式以真首页为准 |
| **微件在页面顶部，脚本早于正文执行** | 设计稿的脚本在预览里位于 body 末尾，搬进微件后 `getElementById` 全返回 null，Swiper 不初始化 | 整体包进 `DOMContentLoaded` |
| **Swiper 没有可用的站内源** | `static.prts.wiki/npm/` 是**按需同步**的镜像，有 `animate.css` 没有 `swiper` | ~~验证阶段临时用 jsdelivr~~ 已传进 `prts-static` 桶的 `npm/swiper@11.2.10/`，见 §8「上线现网」 |

一条好消息：**图不用上传**。12 个入口图标直接用现网那张雪碧图 `background-position` 切
（`模板:Mpbutton` 现在就是这么干的），职业 / 稀有度 / 头像 / 道具 / 模组类型都能映射到现网已有文件，
`{{filepath:}}` 取 URL。只剩活动横幅与家具图现网没有，验证期先引设计稿的 GitHub Pages。

### 上线现网（2026-10-01）：新皮肤还不是默认，新首页先上

`首页` 已经换成新版（rev 431806），**任何皮肤下都能看**，不用等 Arknights 成为默认皮肤。

**非 Arknights 皮肤怎么拿到样式**：同 prts-widgets 的 CharList / VoiceTable——微件里用 JS 加载皮肤自己的

### 修复（2026-10-01）：整块链接拖不出去

**反馈**：新首页的入口格（干员一览 … 公招计算）不能按住拖到标签栏开新标签页，旧首页可以；右键「在新标签页中打开」能用。
其实首页所有 `.mp-a` 格子都这样：入口格、资源卡、轮播候选列表、干员卡、关卡卡、家具卡、打赏按钮、标题栏的「干员一览 »」。

**原因**：第二轮给 `.mp-a > a` 写了 `display: contents`。没有盒子的 `<a>` 在 Chromium / WebKit 里不算「按住的链接」——
两者判断能不能发起链接拖动都是沿**布局树**往上找 `<a>`（Blink `DragController::DraggableNode`、WebKit `DragController::draggableElement` 跳过没有 renderer 的元素），
`display: contents` 的元素不在布局树里，找不到就不拖。右键菜单、中键、点击都按 DOM 找链接，所以照常能用，一直没发现。
Playwright 在 Chromium（CDP `Input.setInterceptDrags`）与 WebKit（`dragstart`）里都复现了；只要 `<a>` 有盒子、`::after` 照样铺满，整格任意位置都能拖。

**改法**（设计稿与适配一起改，prts-design `preview/_src/pages/home.html`）：

| | 做法 |
| --- | --- |
| 设计稿结构 | 整块链接不再写 `<a class>`，直接写成 wikitext 能输出的样子：`<div class="mp-nav__tile mp-a"><a href>…</a></div>`（92 处，类名 / `data-*` 在容器上，`href` / `aria-current` 在链接上）。设计稿预览与现网同构，这类问题在设计稿里就能看到 |
| `.mp-a` 样式 | 从本仓库的 `LINK_SHIM` 挪进设计稿。链接是真盒子：`display` 与 flex / grid 的方向、换行、对齐、间距、轨道全部 `inherit`，`flex: 1 1 auto` + `align-self / justify-self: stretch` + `grid-area: 1 / 1 / -1 / -1` + `height: 100%` 铺满容器内容区，子项排出来与直接放在容器里一样；`::after` 照旧铺满整格接点击 |
| 焦点环 | 画回容器上：`.mp-a:has(> a:focus-visible)`，Hero 三处内缩照设计稿。原来画在 `::after` 上，入口格 / 干员卡这些 `overflow: hidden` 的格子会把外扩的环裁掉——**现网键盘 Tab 到这些格子时看不到焦点环**，一并修掉 |
| 顺带修的 | `.mp-events__item > .ak-icon` 隔了一层 `<a>` 一直没命中（网页活动行的 › 图标尺寸 / 颜色）；标题栏「干员一览 »」「最近更改 »」被 `.mp-a > a { color: inherit }` 压成正文色，回到设计稿的链接色 + 600 字重 + 悬停右移 |
| 本仓库 | `build_mainpage_sandbox.py` 去掉 `LINK_SHIM`、`block_classes`（容器标签设计稿里已定）、脚本补丁 `SCRIPT_PATCHES`（设计稿脚本已改用 `li.querySelector('a')`）；带类名的 `<a>` 直接报错 |

页面正文与 9 个模板的生成结果**逐字节不变**，现网只需重推 `微件:Mpstyle/newskin`（+ purge 首页）。

**现网的手工改动已并回设计稿**：上线后 Rafom 给「关注 & 支持」卡片加了 `skland-hidden`（`首页` rev 432647，森空岛 App 里藏掉充电 / 打赏入口，App 侧按类名藏，站内没有对应样式）。生成器不认识它，`--mainpage` 会冲掉，所以补进设计稿 `home.html`，生成的 `首页` 与现网一致；`首页/sandbox` 随之补上。**以后现网首页再有手工改动，先并回设计稿再跑 `--mainpage`**——推之前 `--dry-run` 看一眼 `首页` 是不是「无变化」。

**验证**：

- 布局：设计稿预览（6 档宽度 × 亮暗）与现网首页换上新样式后（Arknights / Vector 2022 / 旧 Vector / Minerva × 亮暗 × 6 档宽度），
  逐元素比对位置尺寸 + 颜色 / 背景 / 字重 / 下划线：除上表「顺带修的」标题栏 » 链接（现网回到链接色 + 600 字重）和下面两处外零差异。

## 10. 这些对本仓库的机器人意味着什么

能自动做的：

- 扫描（`wikibot scan`）已经能定位全部 `dual-render` / `hardcoded-skin-name` / `legacy-skin-selector` /
  行内 style / 写死颜色的位置。
- 死类名清理（`模板:悖论模拟` 那两个，以及首页重写后残留的 `.mp-*`）是典型的规则活。
- 双份渲染的合并可以先自动出「两个分支的 diff」，把「其实一模一样，直接删一份」和「内容真不同，要人看」分开。
- `PRTS:Gameinfo/国服/基础` 的 `cndlystart`/`cndlyend` 可以由机器人从 gamedata 的 `forceOpenTable` 自动更新，
  让 G8 那块连现有的人工维护也省掉（数据出口不变，编辑随时可以手改覆盖）。

不能自动做的：首页的结构重排、SMW 输出模板的设计、网页活动的内容维护。
机器人负责决定之后的批量落地，以及事后复查——`wikibot scan -t all` 的命中数应当单调下降。
