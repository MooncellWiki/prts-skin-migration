# 移动端表格问题：归类与适配方案

> 数据源：`docs/prts-移动端表格问题页面清单.txt`（799 条：视觉确认 124、复核发现 5、算法检出未复核 670）·
> 实测：现网 `prts.wiki ?useskin=arknights`，Chrome 移动模拟 390×844（Blink，**WebKit 未测**）· 沙箱库 wikitext · 2026-10-03
> §5 复测：同一现网、Chromium 390 宽，清单里 399 页的全部正文表格逐张量结构与问题 · 2026-10-03

## 0. 结论

799 条背后只有**两种机制**，再加一个模板占掉近一半：

| 组 | 条数 | 机制 | 主要修法 | 归属 |
| --- | ---: | --- | --- | --- |
| N 衍生作品导航 | 353（视觉 23） | 手机版导航表 4–5 列，内容列被挤到 65px | 模板 TemplateStyles：<640 逐格堆叠 | 1 个模板 |
| W 撑破（W1–W11、B） | 96（全部人工确认） | 行内 `display:table` / `min-width:Npx` 顶掉皮肤 <640 的 `display:block; overflow-x:auto`；`模板:Code` 定宽 | 皮肤给正文表格包滚动外壳；`模板:Code` 去掉 `min-width` | 皮肤 + 1 个模板 |
| S 竖条（S1–S12） | 102（视觉 10） | 自动表格布局把放不下的表每列压到最小内容宽度（中文 = 一个字）；或表被 `width:75%` 之类缩窄 | 皮肤：手机上已要横滑的表放宽到 ≤3 屏；百分比窄表拉满。个别模板单改 | 皮肤 + 少量模板 |
| Z 误报 / 轻微 | 248 | 敌人头像编号角标、悬浮说明的隐藏文字、单格 >80px | 不处理，抽查确认 | — |

> 246 页、784 张问题表里，真正只能横滑的只有 4 页 6 张，其余换成卡片、属性卡、转置、换行等版式就能读。
> 横滑（§3.1 外壳、§3.2 放宽）降为兜底，落地顺序见 §4。

## 1. 两种症状是怎么来的

### 1.1 撑破（页面横向变宽）

皮肤在 <640 给表格的处理只有一条（`design-system/chrome/responsive.css:140`）：

```css
.mw-parser-output table.wikitable { display: block; overflow-x: auto; max-width: 100%; }
```

它让表格自己当滚动容器。内容里有四种写法让它失效：

| 写法 | 量 | 为什么失效 |
| --- | --- | --- |
| 行内 `display:table` | W 组能在沙箱库找到的 86 页里 **81 页**；正文 893 张表开头里 594 张 | 行内样式压过皮肤，表格不再是块，`overflow-x` 无效。这是当年为了顶掉 Minerva 的 `display:block` 写的，全站成片 |
| 行内 `min-width:750px` | 危机合约日程表 6 页 | 表格是块了，但块本身 750 宽，滚动条在页面上而不在表上（实测 `寻昼行动` 整页 762） |
| 不是 `.wikitable` | 20 张 | 规则只认 `.wikitable` |
| 不是表格 | `模板:Code`（106 处嵌入） | `width:80%; min-width:600px` 的代码框 |

`table-fixed-width` 迁移把定长 `width` 改成了 `min(Npx, 100%)`，但表格**内容的最小宽度**本来就大于屏幕时（11–24 列），宽度写什么都压不住，只能滚。

### 1.2 竖条（列被压成一两个字宽）

自动表格布局下，表格放不下时每列只拿**最小内容宽度**；中文每个字之间都能断行，最小内容宽度就是一个字。所以：

- **撑破的表进了滚动容器后，照样是竖条**。实测 `卫戍协议/2024/敌人一览/冰原武装`：包上外壳后整页回到 390，但 14 列表里表头「攻击范围半径」仍是 47px、6 行。
- **放得下的表也会被挤**：表格被行内 `width:75%` / `65%` 缩窄（手机上这类百分比毫无意义）；或兄弟列有 `nowrap`、定宽、图片，抢走宽度，剩下的文字列只能挤。实测 `异常效果图鉴/恐惧` 的敌人能力表 `width:75%`，只有 328px 宽、13662px 高。

`模板:敌方情报`（3312 个关卡页）其实早就在 ≤700px 时这样处理过：`.stage-enemy-table-scroll` 外壳 + 表格 `width:max-content; min-width:900px; nowrap`，所以关卡页的敌人表没有上榜；上榜的 `BF-1`、`卫戍协议/2024/敌人一览/*`、`沙洲遗闻/战争浪潮` 都是把同款表抄进正文、没带这层外壳。

### Z · 误报 / 轻微（248 条，全是算法检出）

- **Z1 敌人头像编号角标（78）**：只带 `[BADGE]XX10；[BADGE]XX11` 的活动页。指的是 `{{敌人头像}}` 角上用 `transform: scale()` 缩小的编号（`.enemyicon-index`）。实测 `不义之财` 展开后 26×8、单行，落在 40×40 头像里，正常。`[BADGE]html.skin-them…` 是把 TemplateStyles 的 `<style>` 文本读了进去
- **Z2 轻微（170）**：单格 >80px 或 <6 行，如集成战略「招募券」99px×6 行、指标详情 147px×6 行
- 带 `[TBL-SCROLL]w≈1300` 的关卡页（CW-7、GT-3、RA-1…）多是**已经在滚动容器里**的 `模板:敌方情报`，本身不是问题；同条里另一个签名才是检出原因

算法的两个系统性偏差，人工复核时要知道：**行数 = 格高 ÷ 行高**（格里有图标就虚高）；**文字取 `textContent`**（`display:none` 的悬浮说明、`<style>` 都算进去）。

## 3. 适配方案

> 2026-10-03 起，§3.1 / §3.2 的横滑只给 §5 里「真二维」和归不了类的表兜底，主方案是 §5 的换版式。下面保留原方案与实测。

### 3.1 皮肤：正文表格包滚动外壳（解决 W 组）

把顶层表格（不在别的表格单元格里、不浮动、不绝对定位）包进 `<div class="ak-table-scroll">`（设计系统 `base/tables.css` 里已有这个类：`overflow-x:auto; max-width:100%`），同时删掉 <640 那条 `table.wikitable { display:block }`。

- 滚动交给外壳，表格保持 `display:table`：行内 `display:table`、`min-width`、定宽、非 `.wikitable` 都不再影响页面宽度；
- 顺带修掉现有规则的副作用：`display:block` 的表格里，单元格是按内容收缩的匿名表格，窄表填不满自己的边框——这正是编辑们成片写 `display:table` 的原因。

实测（脚本在页面里包外壳后量）：

| 页面 | 改前整页宽 | 改后 |
| --- | ---: | ---: |
| 危机合约/寻昼行动（日程表 `min-width:750px`） | 762 | 390（表在外壳里横滑） |
| 卫戍协议/2024/敌人一览/冰原武装（13 张 14 列敌人表） | 696 | 390 |

实现位置：

- **首选服务端**：`SkinHooks` 加 `OutputPageBeforeHTML`，用 Remex / `HtmlFormatter` 改正文 DOM。不跳动，不依赖脚本；
- 也可以先上 JS（`mw.hook('wikipage.content')`），代价是首屏的宽表加载后跳一下。

要注意的：

- 只在 <640 让外壳滚动，还是全宽度都滚：桌面上超宽表（如 1250px 的合约矩阵）现在溢出正文栏，全宽度滚动更干净，但桌面渲染会变，要另测；
- 外壳里 `position:sticky` 的表头（`.ak-sticky-head`）会改为相对外壳吸顶；
- 嵌套在 inline-block / flex / 单元格里的表跳过（同 `table-fixed-width` 的跳过规则）；
- 外壳上下边距接表格原来的 `margin`，表格自己的上下边距清零（`base/tables.css` 已有 `.ak-table-scroll > .wikitable { margin: 0 }`）。

### 3.2 皮肤：手机上给表格留出可读宽度（解决 S 组大半）

只在 <640 生效，两条：

1. **百分比宽度 <100% 的表拉满**。旧移动站 Minerva 一直是 `width:100% !important`，手机上没人需要 75% 宽的表。
2. **已经要横滑的表，宽度放到 `min(内容最大宽度, 3 屏)`**。反正已经要滑，多滑一点换来每列能读。要量内容宽度，只能 JS 做；CSS 近似是 `模板:敌方情报` 那套 `width:max-content` + `nowrap`，但对长文字列会拉得过宽。

实测：

| 页面 / 表 | 现状 | 拉满 366 | 1.5 屏 549 | 2 屏 732 | 3 屏 1098 |
| --- | --- | --- | --- | --- | --- |
| 恐惧 · 敌人能力表（内容最大宽 3708） | 328 宽、高 13662 | 高 9084 | 高 3624 | 高 2658 | 高 2091 |
| 恐惧 · 干员技能表（997） | 275 宽、高 2854，最窄格 49px×10 行 | 1321，49px×4 行 | 796，69px×6 行 | 712，无竖条 | 565 |
| 冰原武装 · 敌人表（1107–1163） | 666–684，表头 47px×6 行 | — | — | — | 1098，无竖条 |

触发条件建议：表格有单元格「宽 <5em 且 >6 行」才放宽，避免把本来好好的表变成横滑。放宽倍数 2–3 屏，2 屏对文字表已经足够。

### 3.3 模板（逐个，按影响排）

## 5. 细分复测：按手机版式归类（2026-10-03）

### 5.4 实现

都只在 ≤639 生效，桌面不变。类名在设计系统里定，下面用版式名代称。

- **卡片**：`tr` / `td` 改块，格前的列名用 `attr(data-label)`。
  `data-label` 由皮肤脚本按表头抄到每格，只写属性、不挪节点（table-fit 包外壳要挪节点，表里的 iframe 会重载）。没有 JS 时照样堆成卡片，只是没有列名。
- **属性卡**：卡片的变体，前 N 格并成卡头，其余格排三列网格，N 写在表格属性上。
- **转置**：`tbody` / `tr` 设 `display:contents`，表格设 `display:grid; grid-auto-flow:column; grid-template-rows:repeat(原列数, auto)`，原来的第 i 行就排成第 i 列。
  前提是没有跨行 / 跨列格，通栏标题行要先改成 `|+` 表题。
- **分栏折叠**：`tr { display:grid; grid-template-columns: repeat(k, auto 1fr) }`，「数量 | 奖励 | 数量 | 奖励…」折成每行一对。
- **图标换行**：`tr { display:flex; flex-wrap:wrap }`，行头 `flex-basis:100%`，同 `衍生作品导航`。
- **两格上下排**：两格都改块，上下排。
