## 问题

用户反馈：新皮肤下视口 1000px 左右时 [情报处理室](https://prts.wiki/w/情报处理室) 的播放按钮消失，手机上可见但很小。

`模板:剧情简介` 一行三格：关卡格 `width:120px`、简介格 `width:620px`、播放格不定宽，只装一张
`[[文件:情报处理室 播放按钮.png|50px]]`。皮肤 `base/media.css` 的 `.mw-file-element { max-width:100%; height:auto }`
让这张图的最小内容宽度计 0（百分比 `max-width` 的替换元素按「可压缩」处理），播放格的最小宽度只剩 2px 内边距：

- **桌面版式（≥640）**：自动表格布局先满足两列定宽格，播放格只分剩下的。内层表外面还有 160px 的封面列、外层表 `max-width:1000px`，
  内层表最宽约 817px，减去 120 + 620 和内边距最多剩 38px；正文栏窄于约 964px 时一点不剩——播放格 2px、按钮 0×0。
  对应视口 640–约 1050、出侧栏后 1200–约 1700（正文栏 1440 宽时只有 870）。
- **手机版式（<640）**：关卡格 `20vw`、简介格和播放格不定宽，剩余宽度按内容宽度比例分，按钮 50px 对简介几百 px，只分到 6–20px。

| 环境 | 播放格 | 按钮 |
| --- | ---: | ---: |
| 新皮肤 360 / 390 / 600 | 8–13 / 9–14 / 23 | 6–18 / 7–20 / 12–36 |
| 新皮肤 640–1024、1200–1440 | 2 | **0** |
| 新皮肤 1100、1366 | 38 | 36 |
| 旧 Vector 1000 | 52 | 50（被压的是两列定宽格：89 / 440） |
| Minerva 390 | 29–30 | 27–33 |

Vector 没有那条 `max-width`，所以桌面的「消失」是新皮肤带来的；手机上「小」Minerva 也有，只是轻些。

## 改法

`模板:剧情简介` 播放格里的图外套一层：

```
| class="event-story-play" style="background-color:#F0F0F0;"|<span style="display:inline-block;width:50px">[[文件:情报处理室 播放按钮.png|50px|link=…]]</span>
```

图的 `max-width:100%` 有了确定的参照（50px），格子最小宽度回到 52px，被压的变成定宽格 / 简介格。只改模板一行，不加样式页；
Minerva 的 `max-width` 一并失效（那边按钮也回到 50px），Vector 不变。手机上简介列跟着窄一些（390 宽 250 → 212）。

## 同页的另外三处宽度问题

### 桌面封面导航表撑宽整页

页首「公共事务实录 / 特别行动记述」两张 `nomobile` 表：表头格 `width:1000px`、横滑封面条 `<div style="overflow:auto;width:1000px">`。
正文栏窄于 1000px 时表伸出正文栏、整页能横向拖（1000 宽视口整页 1047，Vector 1000 宽整页 1207）。

改成表 `width:100%; max-width:1000px; table-layout:fixed`，去掉表头定宽，封面条 `width:100%`。
`table-layout:fixed` 不能省：自动布局下封面条的最小内容宽度是整排不换行的封面（一万多 px），百分比宽度压不住。

### 手机索引表填不满

两张 `nodesktop` 索引表在 <640 吃皮肤的 `table.wikitable { display:block }`：表的边框占满正文栏，
单元格是按内容收缩的匿名表格，右边空一截（600 宽时 576 里只占 487 / 359）。这是 `docs/移动端表格问题归类与适配方案.md`
§3.1 记过的副作用，皮肤层的外壳方案没上线；行内补 `display:table; width:100%`（编辑们对付这条规则的通行写法），三列短链接不会撑破。

### 特别行动记述的封面不见

「特别行动记述」20 张表左边一格只放 160px 封面（`!rowspan=… class="nomobile"`），右边三列按钮格各 `width="33%"`。
封面图的最小宽度因 `max-width:100%` 计 0，三列百分比把宽度分光，封面列只剩 21px、图 0×0——**所有宽度都是**（不是只有窄屏）。
同一个机制，兄弟列是百分比宽而不是定宽。

这次不能只给图套 160px 外壳：封面 + 三个写死 174px 的 `{{剧情跳转}}` 至少要 789px，正文栏 < 789（视口 640–约 880）时
20 张表全部伸出正文栏（页内实测整页 834）。所以拆成两条，写进页面已经引着的 `模板:情报处理室/styles.css`（插在 theme-os 区块前）：

```css
.intelligence-room-story-table > tbody > tr > th.nomobile[rowspan] .mw-file-element { max-width: none; }
@media (min-width: 640px) and (max-width: 899px) {
	.intelligence-room-story-table > tbody > tr > th.nomobile[rowspan] { display: none; }
}
```

隐藏封面列就是手机版式的排法，表结构本来就适配。只选 `[rowspan]` 的封面：「公共事务实录」51 张表的封面旁边是 `width:100%` 的滚动容器而不是百分比格子，
现在随列宽 64–157px，看得见，不动。试过封面格 `width:16%`：封面 48–131px、永远到不了 160，窄时仍是 0，没选。

## 全站扫描：只放一张文件图的格子被挤小

`scripts/file_cell_squeeze_scan.mjs`，2026-10-04，现网新皮肤、Chromium。主名字空间 19537 个非重定向页，跳过剧情文本页

`[[文件:]]` 图，且图比 `width` 属性小 10% 以上。图片请求一律回 1×1 透明 PNG（宽度靠属性，不影响列宽；对过 `落叶逐火`，结果与真图相同）。
设定宽超过正文栏一半的「大图」按栏宽缩放是预期行为，单独标出、不算问题。分组明细见 [`scan-summary.md`](scan-summary.md)。

结果：1000 宽 3534 页 30072 格，390 宽 5039 页 43750 格。四个模板占了 3875 页，其余 1100 页零散（压到一半以下的 164 页）。

机制分四类，修法不一样：

- **A1 收缩外壳循环**：图外面是按内容收缩的 `inline-block`（`.enemyicon`），图的 `max-width:100%` 又以外壳为参照，最小宽度计 0。同 `item-icon-shrink`。
  修法：外壳行内写定宽（= 设定宽），或类 + `max-width:none`。
- **A2 兄弟列抢宽**：自动布局里旁边是百分比宽（`33%` ×3、`70%`/`30%`）、定宽或长文本的列，图标列只分剩下的或按内容宽度比例分。
  修法同播放按钮（图套定宽外壳）；兄弟列定宽 / 按钮写死时要看总宽放不放得下，放不下就得在窄宽度隐藏或换版式（同情报处理室封面）。
- **B 固定布局**：`table-layout:fixed`，格子宽度按百分比定死，和内容无关；图缩小是因为格子本来就窄，去掉 `max-width` 图会伸出格子。
  要改得调列比例或手机换版式（`docs/移动端表格问题归类与适配方案.md` §5）。
- **C 图比分到的列宽**：横幅 / 导航大图在等分列里按列宽缩，预期行为。

结论：**不在 `模板:敌人头像` 里一刀切**。改成调用方显式开启——`模板:敌人头像` 加可选参数（如 `定宽=1`），
有值时外壳写 `style="width:{{{px|130}}}px"`；`敌方情报`、`敌方情报pro`、`敌人信息/common2`、`特殊敌方情报` 的 6 处调用传这个参数。
`登场敌人`、`集成战略` 等固定布局的不传，维持现状（B 类，格子本来就窄）。
