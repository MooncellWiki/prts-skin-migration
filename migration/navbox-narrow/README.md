# navbox 窄屏撑宽（`navbox-narrow`）

2026-10-01 · 机器人账号 BotCathPalug · `模板:Navbox/styles.css` r431860 · 脚本 `scripts/navbox_narrow_apply.py`

## 问题

与表格定宽（`../table-fixed-width/`）同类：内容的最小宽度大于容器，手机上整页被撑宽、能左右拖。
起因是 [VEC-07 萌芽之时](https://prts.wiki/w/VEC-07_萌芽之时) 底部的「活动关卡一览」在 390 宽下是 408px（容器 366）。

这里没有写死的宽度，是 `nowrap` 叠出来的：

- `th.navbox-group` 本来就 `nowrap`（列表列 `width:100%`，分组列只能拿到最小内容宽度，必须靠它撑住），
  嵌套 navbox 每一层都多一列分组；
- 列表项 `.navbox .hlist li` 与链接（站点 CSS 的 `.nowraplinks a`）也不换行，最长的一项整块算进最小宽度。

三层分组（110 + 73 + 61）加上最长一项「IG-EX-11 密探有专车接送」（148）就是 408。
旧移动站没出过事，是因为 Minerva 根本不显示 navbox。

修复前，新皮肤下默认状态（不点开任何折叠）就撑宽的：

| navbox | 最小宽度 | 撑宽的宽度范围 |
| --- | ---: | --- |
| 内测剧情导航（`.nomobile`） | 775 | 平板 640–860 |
| 剧情导航（`.nomobile`） | 576 | 平板 640–665 |
| 道具导航 | 455 | 所有手机 |
| 关卡导航 | 408（依当前页而定，全部展开 499） | 所有手机 |
| 危机合约 | 343 | ≤360 的手机 |
| 集成战略 | 308–320（展开 352） | ≤360 的手机 |

## 改法

`模板:Navbox/styles.css` 布局部分末尾加一段（`layout:begin/end navbox-narrow` 标记，源文件 `navbox-narrow.css`）：

- **≤1119px**：列表项改 `display:inline-block; white-space:normal`，项内链接跟着放开。
  inline-block 不可拆，所以放得下时照旧整项换行，只有单项比一整行还宽时才在项内折行。
  皮肤的分隔符 `" · "` 写在 `li::after` 里，inline-block 会吃掉末尾空格，给 `::after` 加 `white-space:pre` 保住间距
  （不加的话 VEC-07 在 768 宽下有约 2000 项横向错位）。
- **≤639px**：分组名 `white-space:normal; word-break:keep-all`——只在空格 / 标点处折行，汉字之间不断开
  （不能简单放开 `nowrap`：分组列会被压成一个字宽）；分组列左右内边距 1em → 0.5em。

`.nowraplinks a` 不能整体放开：分组名本身多是链接，放开后同样会被压成一个字宽，所以只放开 `li` 里的链接。

桌面（≥1120）不在任何媒体查询里，渲染不变。

## 没解决的

- ≤375 的手机上点开 `关卡导航 → 日常关卡`：剿灭作战 › 剿灭委托 › 地区三层分组，最深一层有「阿尔斯特甜品制作平台」
  这种没有空格 / 标点的长名，keep-all 下不能断，最小宽度 359，360 宽下多出约 23px、375 宽下约 8px。默认状态不受影响。
- `衍生作品导航`（`.nomobile`）最小 553，640–643 宽多出 3px：它的条目不是 `<li>`，是 `{{·}}` 隔开的裸链接，未处理。
