# 合约矩阵：图标被压小、连线错位（`contract-rune`）

2026-10-04 · 机器人账号 BotCathPalug · 脚本 `scripts/contract_rune_apply.py`

状态：**已上线**（`模板:危机合约词条/styles.css` r434294、`模板:危机合约词条` r434295，正文 31 页 46 张；
日志 `reports/contract-rune/live-run.log`）。上线后清了全部 80 个嵌入页的解析缓存（失败 0）。

## 问题

各 `*/历史合约` 页的「常驻行动地点」等合约矩阵（3 行等级 × 十几到二十几个词条槽），新皮肤下图标缩成一小点，
图标之间的连线悬在半空。桌面 1280 宽下图标 19–47px，手机 390 宽下 0–11px（`荒野 无序矿区/历史合约` 直接是 0）。
Vector / Minerva 正常。

三件事叠在一起：

1. `模板:危机合约词条` 的连线是按 **50px 图标**写死的绝对定位小条（`left:23px; top:30px; height:18px` 等），
   长度 = 两个单元格内边距 + 一条边线。图标尺寸或间距一变就对不上。
2. 新皮肤 `.mw-file-element { max-width:100%; height:auto }`：单元格里的图标对表格的最小宽度贡献是 0，可以被压缩。
   旧皮肤的图片没有这条，表格按内容宽度撑开。
3. table-fixed-width 批次把这些表的 `width:1300px` 改成了 `width:min(1300px, 100%)`（如 r431367），
   mobile-table 第四步又包了 `ak-table-scroll` 外壳。表宽成了外壳的 100%，于是不横滑、先压图标。
   那两批的验证只量表格的位置尺寸，量不到「图标缩了、连线错位」。

另外两处新皮肤和 Vector 的差异，图标恢复 50px 之后才显出来：

- 新皮肤 `.wikitable` 单元格内边距 `0.45em 0.7em`，Vector 是 `0.2em 0.4em`，图标间距变大，连线短一截；
- 表格按最小宽度排版时，行首的「等级 1」折成一字一行，3 行字高过图标，把整行撑高约 8px，竖向连线够不到下一行。
  Vector 在 1280 宽下同样如此，只有宽屏（表格放得下）时才是设计的样子。

## 改法

不改皮肤，旧皮肤渲染不变。

1. **新建 `模板:危机合约词条/styles.css`**（`模板_危机合约词条_styles.css`）：
   - 连线长度的基础值（18px / 27px，原来写在行内）；
   - `body.skin-arknights`：连线各补长 0.6em；`.prts-cc-matrix` 里的图标 `width:max-content`（不让压），
     行首格 `white-space:nowrap`。
2. **`模板:危机合约词条`**：引入样式；图标外壳加 `prts-cc-rune-icon`，两种连线加
   `prts-cc-rune-line-down` / `-right`，连线的 `height` / `width` 从行内样式挪进样式页，其余行内样式不动。
3. **正文**（主名字空间，31 页 46 张带连线的矩阵）：表格加 `prts-cc-matrix` 类；
   其中 13 页 16 张还没包横滑外壳的包上 `<div class="ak-table-scroll">`（写法同 mobile-table 第四步）。
   `危机合约/*/合约详情` 是用 `<section>` 嵌入这些页面的，不用单独改。

为什么要加类：行首格要靠表格上的记号才选得到。TemplateStyles（css-sanitizer 6.2.1）不认 `:has()`，
`tr:has(.prts-cc-rune-icon) > td:first-child` 存不进去。

没有连线的小表（各页的「轮换行动地点」，215 张，500px 宽）不加类：手机上图标照旧随宽度缩，不横滑。
